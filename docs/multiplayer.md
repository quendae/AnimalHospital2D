# Multiplayer architecture

Animal Care Co-op uses a **host-authoritative WebRTC topology**. The existing Colyseus service remains deliberately small: it creates rooms, publishes the lobby roster, handles reconnect/host selection and forwards opaque WebRTC signaling messages. Gameplay traffic moves to WebRTC data channels after peers connect.

## Topology

```text
                    Colyseus :2567
                lobby / signaling only
                  /        |        \
                 /         |         \
              HOST ===== GUEST A     GUEST B
                \\==================//
                   WebRTC data channels
```

The host owns the authoritative clinic simulation. Guests send compact input packets to the host. The host runs collisions, item ownership, patient workflows, stations, spills and minigames, then broadcasts snapshots back to guests. This avoids divergent copies of the current Phaser scene while keeping the high-frequency gameplay path peer-to-peer.

## Lobby flow

1. A player selects one of four heroes and enters a display name.
2. The host creates a `clinic` room; Colyseus returns a room code.
3. Guests join by room code or by a shared URL containing `?room=...`.
4. Colyseus forwards SDP/ICE signaling between the host and each guest.
5. Once data channels are open, the lobby shows `P2P READY`.
6. The host starts the shift. Every client receives the same procedural seed.
7. Gameplay inputs and snapshots use WebRTC rather than Colyseus state patches.

## Reconnection and host changes

The signaling room uses Colyseus automatic reconnection with a 20-second server window. A dropped player stays in the roster as disconnected while the SDK attempts to restore the room connection. P2P links are rebuilt after reconnect.

If the host actually leaves and the reconnect window expires, the signaling room selects the next connected player as host and broadcasts the new host ID. The lobby rebuilds the star topology around that player.

> Host migration during an **active gameplay simulation** is intentionally conservative. The lobby/signaling host can migrate, but the full in-progress world is not yet transferred as a resumable authority checkpoint. A future persistence layer can promote the newest authoritative snapshot for seamless mid-shift host migration.

## NAT traversal

The client ships with public STUN endpoints for development and ordinary NAT traversal. For reliable public Internet sessions, configure a TURN service:

```env
VITE_TURN_URL=turn:turn.example.com:3478
VITE_TURN_USERNAME=animal-care
VITE_TURN_CREDENTIAL=change-me
```

TURN credentials must be deployed securely for production. Do not commit real credentials.

## Character assets

Hero portraits are independent assets under `apps/client/public/portraits/`. Each hero also has a characteristic top-down color/motif generated by the Phaser scene layer. Final painted portraits can replace the SVGs without changing lobby or networking code.

## Playwright coverage

The E2E suite starts both Vite and the Colyseus service automatically. It checks:

- character card selection and local launch;
- room-code deep links;
- a real two-browser host/join flow;
- WebRTC data-channel readiness;
- guest input reaching the host simulation;
- shared procedural seed;
- signaling reconnection;
- host migration while still in the lobby;
- responsive lobby layouts on desktop, phone and tablet, portrait and landscape.

Run locally with:

```bash
npm install
npx playwright install chromium
npm run test:e2e
```

GitHub Actions installs Chromium and runs the same suite for pull requests.
